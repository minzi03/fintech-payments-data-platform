# PR-PORTAL-002 Threat Model

- Status: **ACCEPTED — FROZEN**
- Revision: 1
- Method: focused STRIDE-style analysis of the Portal identity boundary
- Assets: authenticated identity, session authority, environment/tenant isolation, authorization
  decisions, OIDC token material, capability truth, and immutable audit evidence

The browser and all browser-supplied values are untrusted. Only an exact configured OIDC issuer,
the dedicated session store, immutable policy bundle, current capability registry, and append-only
security ledger may contribute authoritative state.

## Detection and incident boundaries

- Metrics never label principal, session, subject, resource ID, or correlation ID.
- Security events carry protected stable references for investigation.
- Repeated callback, refresh replay, session-family anomalies, audit integrity failure, production
  selection denial spikes, and KMS/decryption failures are incident-grade signals.
- Authentication cannot start when session, audit, policy, capability, or provider authority is
  not safe enough to create durable evidence.

## Residual-risk acceptance

The accepted residual risks are limited to the five-minute identity-revalidation window,
same-device/browser compromise, provider limitations around back-channel logout/refresh rotation,
and database-superuser tampering before external integrity checkpoint. These risks require the
controls and runbooks frozen in the main Design Freeze; none permit a fail-open authorization
decision.
